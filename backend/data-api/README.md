# Data API

Bun service for public market data. It ingests spot 1-minute candles from eight exchanges (Binance, Bybit, OKX, KuCoin, Gate, MEXC, Kraken, SafeTrade), indexes Rhea DEX swaps and public NEAR Intents executions from NEAR blocks itself, stores everything in ClickHouse, and serves candles for 15 intervals plus live updates over WebSocket. CoinGecko supplies token metadata (prices, market caps, icons, project links) for the Terminal. It holds no user data.

## Data flow

```text
exchange REST ──(1m pages; native 1h/1d where 1m retention is short)──▶ ingest-<venue> ──▶ ClickHouse candles (only candle writer)
exchange WS ──(trades, 24h tickers)──────────────────────────────────▶ ingest-<venue> ──▶ Valkey: recent minutes, tickers, pub/sub
neardata.xyz finalized blocks ──▶ ingest-near ──▶ Valkey stream near:blocks (Rhea + Intents logs)
near:blocks (+ neardata.xyz gap repair) ──▶ ingest-rhea ──▶ ClickHouse rhea_swaps ──▶ Rhea candles
near:blocks (+ neardata.xyz gap repair) ──▶ ingest-intents ──▶ ClickHouse intents_diffs ──────┐
Intents Explorer swaps + FastNEAR transactions ──▶ ingest-intents ──▶ intents_settlements ──┴─▶ Intents candles
CoinGecko coins/markets + coins/{id} ──▶ token-markets ──▶ Valkey token:markets, token:links
                                       api × N ◀── ClickHouse (history) + Valkey (live edge)
```

- **Exchanges** (`src/venues/*.ts`, `src/binance/`): REST pages fill history from each pair's first minute where the venue serves it; trade streams build live minutes (`src/ingest/minutes.ts`) that REST later settles.
- **Rhea** (`src/venues/rhea/`): every swap on Rhea's classic and DCL contracts, one row per hop. Candles are priced in USD as each swap's wNEAR price times our Binance `NEARUSDC` close of that minute, aggregated over every Rhea pool of the pair. History starts at the indexer's switch minute (`rhea_state`).
- **NEAR Intents** (`src/venues/intents/`): every `token_diff` intent of a successful verifier receipt is stored; 1Click swaps settled by transfers are read from the Intents Explorer and their NEAR transactions. Trades are derived on read, the same way for live and backfilled data: route steps of one 1Click user, settled swaps, then USD pricing ($1 for reviewed stablecoins, else the other asset's exchange close). The Explorer backfill reaches 179 days back from the switch minute. Confidential swaps are not visible.
- **CoinGecko metadata** (`src/markets/`): `token-markets` reads the reviewed asset list from the DYA ID catalog (`DYA_ID_CATALOG_URL`) and refreshes prices and project links into Valkey.
- **Registry** (`registry/seed.json`): the reviewed markets per asset, generated by `bun scripts/generate-registry.ts [SYMBOL…]` from the Terminal's selectable assets, the 1Click catalog, CoinGecko tickers, venue instrument lists and our Rhea swap index. At runtime each source is listed only while its price is within 15% of the 1Click catalog price.

## HTTP API

All endpoints are `GET`, public, and CORS-limited to `CORS_ORIGINS`. Unknown or repeated query parameters return 400. Decimals are exact canonical strings (no trailing zeros): prices keep up to 18 fraction digits, volumes 8.

| Path | Purpose | Cache-Control |
| --- | --- | --- |
| `/v1/meta` | Server time, intervals, page size 1000 and the current revision | `public, max-age=60` |
| `/v1/assets` | Intents identities, admitted primary market and alternatives; explicit unavailable reasons | `public, max-age=60` |
| `/v1/markets` | Admitted markets with stored history: venue, source label, symbol, assetId and first minute; `degraded` is `null`, or `{ cause: "near-intents", since }` while the 1Click catalog is unreachable | `public, max-age=60` |
| `/v1/token-markets` | Last CoinGecko snapshot `{ updatedAt, assets }` keyed by 1Click asset id: USD `price`, `change24h`, `volume24h`, `marketCap`, `image` | `public, max-age=60` |
| `/v1/token-links` | Project links (website, X) of the selectable assets | `public, max-age=300` |
| `/v1/candles?market=binance:BTCUSDT&interval=1m&page=25049&rev=1` | One aligned page | final: `public, max-age=31536000, immutable`; open: `public, max-age=2` |
| `/v1/candles/latest?market=binance:BTCUSDT&interval=1m` | Current page index and bars | `public, max-age=2` |
| `/v1/tickers?markets=binance:BTCUSDT,binance:NEARUSDC` | Rolling 24h snapshots; at most 100 markets | `public, max-age=1` |
| `/v1/intents/coverage?days=7` | NEAR Intents derivation coverage per UTC day: receipts by status, charted and unpriced trades, unrecoverable backfill swaps, and the switch, cursor and backfill positions | `public, max-age=60` |
| `/v1/intents/trades?market=intents:SOL_USD&limit=50` | A NEAR Intents market's newest charted trades of the last 24 h: time, USD price, base quantity, taker side and NEAR transaction hash | `public, max-age=2` |
| `/v1/stream` | WebSocket upgrade for live candles and tickers | — |
| `/healthz` | `ok`, `degraded` (a venue stream is disconnected, a market's sync is behind, or 1Click is unreachable) or `down` (no markets listed), with per-venue stream state and sync lag; 503 only when `down` | `no-store` |

Errors answer `{ error, requestId, revision }`. Candle rows are `[openTime, open, high, low, close, volume, quoteVolume, trades, takerBuyVolume, takerBuyQuoteVolume]`; fields a venue's candles don't publish are `0`, live minutes included. Page `k` covers bucket indices `[k*1000,(k+1)*1000)`; `prev` is null only on the interval's first page. Intervals: `1m 3m 5m 15m 30m 1h 2h 4h 6h 8h 12h 1d 3d 1w 1M`. A missing or wrong `rev` returns 400 with the current revision; `DATA_REVISION` changes every historical page URL.

### WebSocket

```json
{"method":"subscribe","subscription":{"type":"candle","market":"binance:BTCUSDT","interval":"4h"}}
{"method":"subscribe","subscription":{"type":"ticker","market":"binance:BTCUSDT"}}
```

The server acknowledges with `subscriptionResponse`, sends a snapshot (`isSnapshot: true`), then updates: `{"channel":"candle","data":{"market":"binance:BTCUSDT","interval":"4h","seq":1,"isSnapshot":true,"bar":{"t":0,"o":"…","h":"…","l":"…","c":"…","v":"…","q":"…","n":1,"x":false}}}`. `x` marks closure. Each subscription has its own increasing `seq`; after a reconnect or a sequence gap, fetch `/v1/candles/latest` and resubscribe. Clients send `{"method":"ping"}` every 30 seconds and receive `{"channel":"pong"}`. Errors use `{"channel":"error","data":{"code":"…","subscription":{…}}}`.

## Correctness

- Every interval is aggregated with exact decimal sums from stored candles: 1m everywhere, plus native 1h/1d before a market's first whole stored 1m hour on venues with short 1m retention (Gate, MEXC). Each instant is covered by exactly one resolution, on Binance's bucket grid.
- When a bucket traded at all, open/high/low come from candles with volume; close is the last price either way.
- REST is the only writer of ClickHouse candles. Checkpoints (`sync_state`) advance only after rows are stored, so restarts and outages resume without gaps. Duplicate rows collapse in `ReplacingMergeTree`; reads use `FINAL`.
- Minutes after the checkpoint come from Valkey and are merged per minute; Valkey can be flushed at any time.
- NEAR indexers keep a cursor (the last block whose rows are all stored) and re-read missing blocks from neardata.xyz before passing them. Rhea and Intents candles never pass the cursor's minute or the stored minutes of the exchange markets that price them.
- `bun src/main.ts verify <market> [interval…]` compares stored bars with a venue's native candles and exits non-zero on any mismatch.

## Run locally

Requires Bun ≥ 1.4 and Docker.

```sh
cd backend/data-api
cp .env.example .env
bun install --frozen-lockfile
docker compose up -d --wait clickhouse valkey
docker compose run --rm migrate
docker compose up -d api token-markets ingest-binance ingest-near ingest-rhea ingest-intents
```

`compose.yaml` publishes only loopback ports: API `18080`, ClickHouse `18123`, Valkey `16379`. Bun commands run on the host (`bun src/main.ts sync binance:BTCUSDT`, `bun src/main.ts verify okx:OKB-USDT 1h`) use the same `.env`.

Tests:

```sh
bun run typecheck
bun test
# With ClickHouse and Valkey running and migrations applied:
DATA_API_INTEGRATION=1 DATA_API_TEST_DATABASE=market_rest_test bun test
```
